### K8S COmponents:
* In EKS - Master node is managed by AWS 
* eksctl - for creation of eks cluster
    * eksctl uses AWS cli creds to authenticate and create cluster
* kubectl - to communicate or interact with cluster 

* Namespace: ``` kubectl get namespace ```
    * Isolated space/ separation inside cluster 
    * Can run multiple clusters / multiple environments without any dependency

* kind :
    * Type of resource you want to create 
    * example pod 

* apiVersion :
    * Resources are assigned to seperate versoin 
* Resources of two level : ``` kubectl api-resources ```
    1. Namespace level 
    2. Cluster level 

* Everything you create in k8s is a resource including namespace

### pod creation:
* pod is the smallest deployable unit in the k8s

* 2-pod.yaml 
```
apiVersion: v1
kind: Pod
metadata:
  name: nginx
spec:
  containers:
  - name: nginx
    image: nginx:1.14.2
    ports:
    - containerPort: 80

```

* kubectl apply -f 2-pod.yaml 
* kubectl get pods 
* kubectl get pods -o wide 
* kubectl delete -f nginx.yaml

* kubectl get pods -n production

* kubectl describe pod nginx -n production
* Events that happens while creation: 
    * Assign node 
    * pull image to node 
    * create container 
    * start container

* pod can have multiple containers inside it 
* container in pod shares the same network & storage 

* 3-multicontainer.yaml

```
apiVersion: v1
kind: pod
metadata:
    name: multicontainer
    namespace: production
spec:
    containers:
    - name: nginx
      image: nginx
    - name: hello-world
      image: hello-world
      command: ["sleep" , "1000"]
```

* kubectl apply -f 3-multicontainer.yaml
* kubectl get pods -n production
* kubectl describe pod multicontainer -n production
* kubectl exec -it multicontainer -n production -c nginx -- bash    : for multicontainer 

* kubectl exec -it nginx -n production -- bash 

* curl http://localhost in side pod 

* Why we use multi container pods?
    * To ship the logs and metrics to log/metric storages like elk we use multicontainers
    * These are called as side car containers.

### resources 
* resources of a pod can be defined using resources section in pod spec 
* Its a best practice to restrict the resource of a pod , otherwise it consumes the full node resources

* 6-resources.yaml
```
apiVersion: v1
kind: Pod
metadata:
  name: frontend-app
  labels:
    app: web
spec:
  containers:
  - name: web-container
    image: nginx:latest
    ports:
    - containerPort: 80
    resources:
      requests:
        memory: "64Mi"    # Minimum memory guaranteed for the container
        cpu: "250m"       # Minimum CPU guaranteed (250 millicores = 0.25 core) (1cpu = 1000millicore)
      limits:
        memory: "128Mi"   # Maximum memory the container can use
        cpu: "500m"       # Maximum CPU the container can use (500 millicores = 0.5 core)

```

* QOS : quality of service 
• BestEffort (Evicted 1st): No requests and no limits are set; it has no resource guarantees and is instantly terminated when the node faces stress.
• Burstable (Evicted 2nd): Requests are less than limits (requests < limits); it guarantees a baseline but is killed if it exceeds its request while the node is under pressure.
• Guaranteed (Evicted Last): Requests equal limits (requests == limits); it locks in dedicated resources and is only terminated as a final, absolute resort.

### env :

### secret :
* Secrets are used to store secrets in encoded format . It is not the best practice it can be decoded easily 

* 10-secrets.yaml
```
apiVersion: v1
kind: Secret
metadata:
  name: secret-1
data:
    username: "QWRtaW4K"
    password: "VGVzdEAxMjMK"
```

* Encode
```
echo "Admin" | base64  >>>>> QWRtaW4K
echo "Test@123" | base64  >>>>>> VGVzdEAxMjMK
```
* Decode

```
echo "QWRtaW4K" | base64 --decode  >>>>> Admin
echo "VGVzdEAxMjMK | base64 --decode >>>>> Test@123
```
* kubectl apply -f 10-secrets.yaml

* Attach secret to pod :
    * while attach secret , k8s decodes it and adds to the pod 

* 11-secret-pod.yaml
```
apiVersion: v1

  containers:
  - name: web-container
    image: nginx:latest
    ports:
    - containerPort: 80
    envFrom:
      - secretMapRef:
          name: secret-1

```

* kubectl apply -f 11-secret-pod.yaml

### service 
* ips cannot be used as they are not static 
* communication between pods happens via service and also load balancing.
* types of services:   
    * clusterIp
    * nodePort
    * loadBalancer
* 12-service.yaml:

```
apiVersion: v1
kind: Service
metadata:
  name: my-service
spec:
  selector:
    app: web
  ports:
    - protocol: TCP
      port: 80 
      targetPort: 80 # containerport
```

* kubectl apply -f 12-service.yaml
* kubectl describe svc my-service 


* 13-service-test-pod.yaml
